## Step 2 — Initialize Local Git, SSH Remote, and Upstream (plain `git push`)

Use **SSH**, not HTTPS — same pattern as your other projects. After the **first** push with `-u`, everyday pushes are just `git push` (no `origin main`, no PAT).

### Your SSH setup (already configured)

You use `~/.ssh/config` with **Host aliases** so the correct key is picked automatically:

| Host alias | Key | Use for |
|---|---|---|
| `github-personal` | `~/.ssh/id_ed25519` | Personal GitHub (`muhasin-code/*`) |
| `github-bloomberglab` | `~/.ssh/id_ed25519_bloomberglab` | Bloomberg Lab org repos |

**PaperLens is a personal repo** → use the `github-personal` host alias (explicit key selection). Your `churnguard-ai` repo uses `git@github.com:...` which also works because the default key matches; `github-personal` is clearer when you have two GitHub accounts.

### Prerequisites — verify SSH (personal account)

```bash
# Must succeed for personal GitHub
ssh -T git@github-personal
# Expected: Hi muhasin-code! You've successfully authenticated...

# Optional cross-check (default github.com host)
ssh -T git@github.com
```

Do **not** use `github-bloomberglab` for PaperLens — that key is for org repos like `bergie`.

> **Security:** Never paste private key contents (`id_ed25519` without `.pub`) into chat, docs, or commits. Only public keys (`.pub`) belong on GitHub.

### Actions — init repo and remote

From your local project root:

```bash
cd /home/muhasin/ML-Projects/paperlens

# Initialize if not already a git repo
git init -b main

# Personal repo — SSH via github-personal host alias
git remote add origin git@github-personal:muhasin-code/paperlens.git
```

If `origin` already exists with the wrong URL (HTTPS or wrong host):

```bash
git remote set-url origin git@github-personal:muhasin-code/paperlens.git
```

**URL format note:** The host is `github-personal` (from `~/.ssh/config`), not `github.com`. Full form:

```
git@github-personal:<owner>/<repo>.git
         ↑ SSH Host alias     ↑ GitHub owner/repo path
```

Equivalent used by `churnguard-ai` (also valid for personal):

```
git@github.com:muhasin-code/churnguard-ai.git
```

### Actions — enable plain `git push` (upstream tracking)

Upstream is set **once** on the first push (Step 9). After that, `git push` alone works — same as `bergie` and `churnguard-ai`:

```bash
# After first push (Step 9), verify upstream:
git config --get branch.main.remote    # → origin
git config --get branch.main.merge     # → refs/heads/main

# Everyday workflow thereafter:
git push
```

If upstream is ever missing, fix without re-pushing:

```bash
git branch --set-upstream-to=origin/main main
```

Optional global convenience (if not already set):

```bash
git config --global push.default current
git config --global push.autoSetupRemote true
```

### Troubleshooting

| Problem | Fix |
|---|---|
| `Permission denied (publickey)` | Wrong host alias — use `github-personal`, not `github-bloomberglab` or HTTPS |
| `Could not read from remote` | Run `ssh -T git@github-personal`; confirm repo exists on GitHub under `muhasin-code` |
| `git push` asks for upstream | Run once: `git push -u origin main` |
| Remote shows `https://` | `git remote set-url origin git@github-personal:muhasin-code/paperlens.git` |
| Wrong GitHub account | Check remote host: personal = `github-personal`, Bloomberg = `github-bloomberglab` |
