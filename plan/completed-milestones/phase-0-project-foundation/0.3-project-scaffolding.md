## Step 1 — Update `.gitignore` and Create Directory Structure

### Why before directories

Git does not track empty directories. The only way to commit a directory structure without
source files yet is to place a `.gitkeep` marker file inside each directory. We update
`.gitignore` first so the new `data/chroma/` path is correctly ignored before we create it,
and so `.gitkeep` files are never accidentally excluded.

### Actions — update `.gitignore`

Open `.gitignore` and make two changes:

**1. Fix the ML/data section.** The current entry has `chroma/` (root-level only). Replace it
so it also catches `data/chroma/`:

```
# ML / data
data/raw/
data/processed/
data/chroma/
*.pt
*.bin
*.safetensors
chroma/
.cache/
models/
```

**2. Add at the end of the file:**

```
# Git directory placeholders — never commit .gitkeep files in editor outputs
!**/.gitkeep
```

The `!**/.gitkeep` negation ensures .gitkeep files are always tracked regardless of other
patterns (e.g. `data/raw/` is ignored, but `data/raw/.gitkeep` is not).

## Step 2 — Add Dependency Manifests

### Rationale: two files

Runtime code (`requirements.txt`) and development tooling (`requirements-dev.txt`) are kept
separate so deployment environments can install only runtime deps without pulling in linters
and test runners. The CI workflow installs both; production only needs `requirements.txt`.

### Why no LangChain

The blueprint tech stack lists direct integrations: sentence-transformers, ChromaDB, rank_bm25,
ollama client. LangChain is a high-level abstraction over these exact tools. Including it adds
a heavy transitive dependency tree, masks the underlying architecture in code, and contradicts
the interview story: "I built the pipeline from direct integrations." Remove it entirely.

## Step 6 — Set Up Pre-Commit Hooks

### Rationale: ruff only (not ruff + black + isort)

ruff 0.1+ ships its own formatter (`ruff format`, equivalent to black) and handles import
sorting via its `I` rules. Running black and isort alongside ruff causes conflicts — they
have slightly different opinions on trailing commas and import grouping, producing infinite
fix-revert loops in pre-commit. The modern practice (as of 2024+) is to drop black and isort
entirely and use ruff for everything. This is the approach used here.

### Actions — create `.pre-commit-config.yaml`

```yaml
# See https://pre-commit.com for documentation
# ruff handles linting, formatting, and import sorting — no separate black or isort

repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.6.9    # pin to a specific version; update periodically
    hooks:
      - id: ruff
        args: ["--fix", "--exit-non-zero-on-fix"]
        name: ruff (lint + auto-fix)
      - id: ruff-format
        name: ruff-format (formatter)

  # Optional but useful: catch common issues before they reach CI
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.6.0
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
      - id: check-yaml
      - id: check-added-large-files
        args: ["--maxkb=500"]    # prevent accidental model/data file commits
      - id: check-merge-conflict
      - id: debug-statements
```

### Actions — add ruff configuration

Add a `[tool.ruff]` section to a new `pyproject.toml` at repo root. This file handles tool
configuration only — no build system is needed since we use `requirements.txt` for deps.

```toml
[tool.ruff]
target-version = "py311"
line-length = 100
src = ["src", "tests"]

[tool.ruff.lint]
select = [
    "E",   # pycodestyle errors
    "W",   # pycodestyle warnings
    "F",   # pyflakes
    "I",   # isort (import sorting)
    "B",   # flake8-bugbear
    "C4",  # flake8-comprehensions
    "UP",  # pyupgrade
]
ignore = [
    "E501",  # line too long — handled by formatter
]

[tool.ruff.lint.isort]
known-first-party = ["src"]

[tool.pytest.ini_options]
testpaths = ["tests"]
asyncio_mode = "auto"
```

### Actions — install and verify hooks

```bash
source .venv/bin/activate

# On a fresh repo with minimal code this should pass clean
```

If ruff reports issues in `src/paperlens/main.py` on the first run (e.g. missing type

## Step 7 — Add Initial CI Workflow

### Actions

Create the directory and file:

```bash

```

Create `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  push:
    branches:
      - main
      - "feature/**"
      - "fix/**"
      - "chore/**"
  pull_request:
    branches:
      - main

jobs:
  lint-and-test:
    name: Lint & Test (Python 3.11)
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Set up Python 3.11
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"
          cache: "pip"

      - name: Install CPU torch
        run: |
          pip install torch --index-url https://download.pytorch.org/whl/cpu

      - name: Install runtime dependencies
        run: |
          pip install --upgrade pip
          pip install -r requirements.txt

      - name: Install dev tools
        run: |
          pip install -r requirements-dev.txt

      - name: Run ruff lint
        run: |
          ruff check src/ tests/

      - name: Run ruff format check
        run: |
          ruff format --check src/ tests/

      - name: Run tests
        run: |
          pytest tests/ -v
```

> **Note:** The CPU torch install step is explicit here. GitHub Actions' ubuntu-latest runner
> has no CUDA GPU, so the CPU wheel is correct for CI regardless of deployment target. The
> install is separated from `pip install -r requirements.txt` for the same reason as locally:
> sentence-transformers' setup.py would otherwise pull the default (CUDA) torch.

> **CI cache:** The `cache: "pip"` directive in setup-python caches pip's download cache
> between runs. torch (~200 MB for CPU wheel) benefits significantly from this.

## Step 8 — Write `docs/architecture-overview.md`

### Actions

Create `docs/architecture-overview.md`:

```markdown
# PaperLens — Architecture Overview

This document provides a narrative description of the PaperLens system architecture.
For visual representations, see the linked diagrams at the end of this page.

---

## System Purpose

PaperLens is a research intelligence platform that ingests ML/AI papers from arXiv,
indexes them for retrieval, and answers natural language queries with cited, grounded responses.
A secondary capability — structured paper intelligence extraction — is powered by a fine-tuned
model. The system is designed to run entirely on open-source tooling with no paid API
dependencies.

---

## Component Overview

### Ingestion Layer (Phase 1)

Papers are fetched from arXiv using the arXiv Python API. PDFs are parsed with PyMuPDF
into section-aware chunks (600 tokens, 100-token overlap). Each chunk carries metadata:
paper ID, title, authors, section label, and position.

### Retrieval Layer (Phase 1–2)

Two parallel indexes power retrieval:

- **Semantic index** (ChromaDB): chunks embedded with `BAAI/bge-large-en-v1.5` via
  sentence-transformers.
- **Keyword index** (BM25): sparse retrieval over the same chunk corpus using `rank_bm25`.

At query time, both indexes return candidate lists. Reciprocal Rank Fusion (RRF) merges
them, and `cross-encoder/ms-marco-MiniLM-L-12-v2` reranks the top 20 candidates to
produce the final top 5 context chunks.

### Generation Layer (Phase 1)

Ollama serves `phi4-mini` locally (CPU inference on the development machine; larger models
on deployment). A versioned YAML prompt in `configs/prompts/` enforces grounded answers —
the LLM must cite the source chunk or refuse to answer. Responses are validated with
Pydantic before being returned.

### Extraction Layer (Phase 3)

A QLoRA fine-tuned variant of `Qwen2.5-3B-Instruct` handles structured extraction queries
(research question, method, datasets, metrics). The query router in the FastAPI layer
classifies each incoming request and directs it to either the RAG path or the extraction
path.

### API Layer (Phase 1)

FastAPI serves the `/query` endpoint (Phase 1 blocking; Phase 4 SSE streaming). Pydantic
schemas enforce request/response contracts. All inference calls pass through Langfuse
instrumentation (Phase 4) for tracing.

### Evaluation & CI (Phase 4)

A gold dataset of 75 curated QA pairs lives in `eval/gold_dataset.jsonl`. GitHub Actions
runs Ragas (faithfulness, answer relevancy, context precision) against this dataset on
every PR. A faithfulness score below 0.75 fails the build.
```

## Troubleshooting

| Problem | Cause | Fix |
|---|---|---|
| `ModuleNotFoundError: src` when running pytest | `src/` not on PYTHONPATH | Run pytest from repo root with `pytest tests/` (not from inside `src/`) |
| `ruff: command not found` | dev deps not installed | `pip install -r requirements-dev.txt` |
| `pre-commit run` fails: `ruff` hook not found | hook version mismatch | `pre-commit clean && pre-commit install` |
| torch downloads ~2.5 GB CUDA wheel | pip default index used | `pip install torch --index-url https://download.pytorch.org/whl/cpu` first |
| `sentence_transformers` import fails after torch install | wrong torch variant installed | `pip uninstall torch -y` then reinstall CPU version |
| CI fails on "ruff format check" | files not formatted before push | `make format` locally, then commit and push the changes |
| CI torch install slow (>10 min) | pip cache miss | Normal on first run; subsequent runs use the `cache: pip` directive |
| `chromadb` install fails: `sqlite3` version | Ubuntu 22.04 ships sqlite 3.37; chromadb ≥0.5 needs 3.35+ | Should be fine on 22.04; if not: `pip install pysqlite3-binary` |
| `git add src/` adds nothing | `src/paperlens/.gitkeep` was removed but `__init__.py` not created | Run Step 3 actions; verify `src/paperlens/__init__.py` exists |
| `check-added-large-files` hook blocks a commit | accidentally staging model/data file | Unstage the file: `git reset HEAD <file>`; add it to `.gitignore` |
